# ADR 0001: Contract additions needed to implement the runtime

Status: accepted (Phase 1, 2026-10-10)

## Problem

The supplied API and Prisma schema could not support a working upload-to-result flow:

1. `POST /upload-url` requires a `consent_receipt_id`, but no route created or withdrew consent receipts.
2. `AssetReceipt.faces` returns opaque face IDs, but no table stored them, so the server could not verify a `face_id` belonged to the asset and owner.
3. `JobPayload.stage` had no column, `UploadAsset` had no creation time (needed for orphan cleanup and grant rate limits), no normalized dimensions, and no purge retry fields.
4. `result_cdn_url` needed a concrete private gateway.

## Decision

- Add `POST /api/v1/consents` and `DELETE /api/v1/consents/{id}` with `ConsentRequest`/`ConsentReceipt` wire models (Pydantic source, regenerated OpenAPI and JSON Schema, hand-synced TS declarations). Withdrawal revokes dependent assets and tombstones their jobs in the same transaction.
- Add `AssetFace` (box + five alignment points + score, owner-bound composite FK to `UploadAsset`). No recognition embeddings are stored. Rows are deleted when the source asset is purged.
- Add `ImageJob.stage`, and `UploadAsset.createdAt`, `normalizedWidth/Height`, `purgeAttemptCount`, `nextPurgeAt`.
- Add `GET /api/v1/media/{token}`: an HMAC capability (job, owner, fence, expiry ≤15 s) re-checked against the database on every access. `result_cdn_url` is this relative path; it rotates on each status read.
- Executable migrations live in `db/migrations/`: `0001` is generated by Prisma 6.19.3 from `docs/schema.prisma`, `0002` is the documented raw constraint file (checked for drift by `scripts/static_check.py`), `0003` adds runtime constraints and the `job_events` NOTIFY trigger used by long polling.

## Alternatives

- Embedding consent in the upload request: rejected; consent must be a durable, withdrawable record.
- Storing face geometry only in Redis: rejected; PostgreSQL is authoritative and the rows are purged with the asset.
- Stateless media URLs pointing straight at S3: rejected; a presigned S3 URL cannot be revoked by a tombstone.

## Compatibility

Additive for existing clients. Generated OpenAPI/JSON Schema changed; TS declarations updated in `packages/shared-types/index.ts`.
